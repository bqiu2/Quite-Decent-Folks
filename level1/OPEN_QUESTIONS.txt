第一关仍需确认的问题
====================

更新日期：2026-08-11

一、评分公式

1. 当前描述中的括号不完整，需要把公式重新写成无歧义的数学表达式。
2. 五类营养物分数使用 shared_game_data.py 中的 0.0~1.0，还是显示层的 0~100？
3. “实际的害虫分数”具体指：
   - PlantStatus.pest（1.0 表示没有害虫，越高越健康）；还是
   - 第一关碰到害虫的次数 pest_hits；还是
   - 另一个 0~100 的数值？
4. 已确认害虫碰撞只伤害人物、不修改植物状态。这样结算时的害虫分数如何变化，
   以及杀虫剂是否仍调用 apply_element(plant, "pesticide") 改善 PlantStatus.pest？
5. “状态分数 = 五类营养物分数之和 - 害虫分数”可能出现 0 或负数，
   需要规定初始状态分数为 0 时如何避免除零，以及负分是否截断为 0。
6. 公式最后乘以 1000，但 Level1Result.score 的共享约定建议为 0~100。
   第一关最终分数范围是 0~100、0~1000，还是先算原始分再归一化到 0~100？

二、地图与障碍

7. “地图滚动速度由快到慢”与“60 秒时为初始速度的 2.5 倍”相互矛盾。
   暂理解为匀加速：v(t) = v0 * (1 + 1.5 * t / 60)，请确认。
8. 初始滚动速度 v0 尚未给出，需要确定像素/秒数值。
9. 障碍初始每 3(+/-0.5)秒生成一次。随着地图加速，生成间隔保持按时间固定，
   还是按地图距离固定并随速度缩短？
10. 上下两层如何切换尚未明确：通过跳跃落到平台、下落穿过平台，还是固定轨道切换？
11. 需要确定障碍物尺寸、碰撞箱，以及生成器如何保证任何组合都有可行路线。
12. 哪些障碍必须二段跳、哪些必须滑铲，以及二段跳障碍最早出现的时间尚未规定。

三、元素生成

13. 每次出现两个不同元素是否采用“不放回抽样”，即同一对中绝不重复？
14. 元素概率是在“元素出现”后降低，还是玩家实际收集后降低？
15. 每次降低的概率值、单个元素的最低概率、概率恢复/重置时机尚未规定。
16. “减少部分均匀分配给其他本次未出现的元素”需要确认是分配给其余四种元素，
   还是只分配给历史上尚未出现过的元素。
17. 两个元素与障碍能否同时出现，以及二选一岔路如何保证上下路线都可到达尚未规定。

四、动作控制

18. 举左手触发跳跃、举右手触发下蹲已暂定，但需要确定关键点阈值和首次校准方式。
19. “动作执行期间不检定其他动作”与“允许空中触发二段跳”存在冲突。
   需要明确第一跳的动作锁何时结束，以及空中第二次举左手如何被识别为第二跳。
20. 跳跃、二段跳和滑铲动画各持续多少秒尚未规定。
21. 双手同时举起、关键点短暂丢失、左右手识别反转时应返回什么动作尚未规定。
22. 主程序传入的 frame 是 OpenCV BGR 还是已经转换好的 RGB，尺寸是否固定尚未规定。
23. 摄像头由主程序持有时，第一关是否显示摄像头预览仍未确定。

五、工程与资源

24. 游戏目标帧率尚未确定，建议统一为 60 FPS 后再调物理参数。
25. README 写的是 game_data.py，但仓库实际统一接口是 shared_game_data.py，需要团队确认 README 命名。
26. README 没有 assets/models/，但环境说明要求 pose_landmarker.task 等模型放在该目录。
   需要确认模型来源、文件名，以及大文件是否使用 Git LFS。
27. AI 可以生成火柴人、植物、障碍和背景的位图素材，但还需要先确定像素风格、
   单帧尺寸、动画帧数、透明背景规范和最终素材审核人。
28. 第一关与 main.py 的窗口复用、退出/暂停事件、返回第二关的方式仍按“暂时保留”处理。
